# AVR-X2000

7.1-channel network receiver, model year 2013, last generation before HEOS.
It shares its protocol document with the AVR-E400.

## Sources for this model

- Control protocol v03 (rev 10.1.0, April 2013) for AVR-X2000 and AVR-E400:
  telnet and RS-232C grammar, events, timing notes.
- Recorded responses from two AVR-X2000 units in the `denonavr` library's
  test data: `Deviceinfo.xml`, `AppCommand.xml`, main-zone, Zone 2, Zone 3,
  network-audio and tuner status pages, all from port 80.
- Retailer and review specifications for hardware facts.

No owner's manual is in the project sources yet; it would settle Wi-Fi,
subwoofer outputs and Zone 2 amp assignment.

## Device description

Recorded `Deviceinfo.xml`: `ModelName` `*AVR-X2000`, `CommApiVers` 0210,
`DeviceZones` 2, 55 function names. Relevant names present: the sources,
the surround mode names (`MOVIE`, `MUSIC`, `GAME`, `PURE`, `STEREO`,
`DIRECT`, `PURE DIRECT`, `DOLBY DIGITAL`, `DTS SURROUND`, `MULTI CH STEREO`
and DSP modes), `Quick Select1`–`4`, `Favorite Station1`–`3`, `ToneControl`,
`Restorer`, `SleepTimer`, `PartyMode`, `AllZonePower`, `AllZoneMute`.

Missing, although the telnet document covers them: Audyssey (`MultEq`,
`DynamicEq`, `DynamicVolume`, `RefLevOffset`), `Bass`, `Treble`,
`ChannelLevel`, `SubwooferLevel`, `LFE`, `DynamicCompression`, `CinemaEq`,
`AllZoneStereo`, every video and picture name.

## In this integration

Diagnostics of an AVR-X2000 with Denon AVR Plus 0.3.2 confirm the points
below (Tested, firmware not reported by the receiver).

1. **Port.** The port is chosen from `CommApiVers` and stored with the
   entry: 80 here (Tested). The receiver type is `avr-x`, as in the
   `denonavr` library.
2. **Gating.** Deviceinfo names few functions, so a feature control whose
   name is missing is created when the receiver answers its query at setup.
   The receiver reported MultEQ, Dynamic EQ, Dynamic Volume, reference
   level, tone, LFE, Dynamic Compression, Cinema EQ, loudness and input
   mode values over telnet (Tested); with 0.3.2, which gated on names only,
   it got none of these entities.
3. **Sound modes.** No `OPSML` answer (Tested: the list was empty). The
   modes come from the Deviceinfo function names that have an `MS` command
   in the protocol document; `MULTI CH STEREO` is sent as `MCH STEREO`,
   `PURE` is left out.
4. **Encodings.** Picture values are two digits; `CV?` has no `CVEND` and
   reports unused channels (Tested: 11 channels, the unused ones at 0 dB);
   the All Zone Stereo state comes only from the `MS` event; tuner presets
   may be `A1`–`G8`.
5. **No speaker list.** No `SS…` data, so no channel list for per-channel
   entities; the `CV` trims arrive but have no entities yet.
6. **Identity.** `Deviceinfo.xml` carries no manufacturer, firmware or
   serial number (Tested); the receiver's `/description.xml` on 8080 might.
7. **Sources.** The active network source is reported as `NET`, which is
   not in the Deviceinfo source list (Tested). Renamed and hidden sources
   are in `AppCommand.xml` (`functionrename`, `functiondelete`), not read
   yet.
8. **No HEOS.** No setup API either (Tested: no port answered). Now playing
   would come from the `NSE` lines or `formNetAudio_StatusXml.xml`.

Over HTTP the AVR-X2000 is of little help: its recorded `AppCommand.xml`
replies contain only renamed and deleted sources; tone control and sound
mode requests come back empty. Telnet is the control path for this model.
