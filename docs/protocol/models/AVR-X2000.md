# AVR-X2000

7.1-channel network receiver, model year 2013, last generation before HEOS.
It shares its protocol document with the AVR-E400.

## Sources for this model

- Control protocol v03 (rev 10.1.0, April 2013) for AVR-X2000 and AVR-E400:
  telnet and RS-232C grammar, events, timing notes.
- Recorded responses from two AVR-X2000 units in the `denonavr` library's
  test data: `Deviceinfo.xml`, `AppCommand.xml`, main-zone, Zone 2, Zone 3,
  network-audio and tuner status pages, all from port 80.
- Retailer and review specifications for hardware facts.

No owner's manual is in the project sources yet; it would settle Wi-Fi,
subwoofer outputs and Zone 2 amp assignment.

## Interfaces

| Interface | Status |
|---|---|
| Telnet 23 | Documented |
| HTTP 80: goform, `Deviceinfo.xml`, `AppCommand.xml` | Documented (recorded) |
| HTTP 8080: `/description.xml` | Documented (library) |
| RS-232C | North America model only |
| HEOS 1255, UPnP 60006, setup API 10443, calibration 1256 | Absent; confirm with the port test |

## Device description

Recorded `Deviceinfo.xml`: `ModelName` `*AVR-X2000`, `CommApiVers` 0210,
`DeviceZones` 2, 55 function names. Relevant names present: the sources,
the surround mode names (`MOVIE`, `MUSIC`, `GAME`, `PURE`, `STEREO`,
`DIRECT`, `PURE DIRECT`, `DOLBY DIGITAL`, `DTS SURROUND`, `MULTI CH STEREO`
and DSP modes), `Quick Select1`–`4`, `Favorite Station1`–`3`, `ToneControl`,
`Restorer`, `SleepTimer`, `PartyMode`, `AllZonePower`, `AllZoneMute`.

Missing, although the telnet document covers them: Audyssey (`MultEq`,
`DynamicEq`, `DynamicVolume`, `RefLevOffset`), `Bass`, `Treble`,
`ChannelLevel`, `SubwooferLevel`, `LFE`, `DynamicCompression`, `CinemaEq`,
`AllZoneStereo`, every video and picture name.

## What blocks it in this integration

1. **Port.** `avr/transport/goform.py` reads `Deviceinfo.xml` on 8080 only.
   The config flow therefore reports "cannot connect".
2. **Gating.** Entities appear only for advertised function names. With the
   list above, an AVR-X2000 would get a media player, sources, sound modes,
   tone control, restorer and sleep timer, and nothing for Audyssey or
   levels.
3. **Encodings.** Picture values are two digits; `CV?` has no `CVEND` and
   reports unused channels; the All Zone Stereo state comes only from the
   `MS` event; tuner presets may be `A1`–`G8`.
4. **Missing newer families.** No `OPSML` sound mode list and no `SS…`
   speaker or rename data are expected; renamed and hidden sources are
   available from `AppCommand.xml` (`functionrename`, `functiondelete`).
5. **No HEOS.** Now playing would come from the `NSE` lines or
   `formNetAudio_StatusXml.xml`.

A workable approach for roadmap item 16: detect the generation from
`CommApiVers`, use port 80 for 0210/0250/0300, and gate older receivers on
telnet replies (send the query, create the entity when an answer arrives)
instead of on function names. Each command used that way still needs a
test or an `assumed` marker.

## Until then

Use the official `denonavr` integration, which handles this generation.
