# Denon AVR Plus 1.7.0b1 (beta)

**Under the hood: one source for which entities there are, a checked
protocol profile, explicit start paths, and the integration's own
bookkeeping out of the options. Almost nothing changes for you; this beta
is to make sure of that.**

A pre-release: HACS offers it only with *Show beta versions* switched on for
Denon AVR Plus. Needs **Home Assistant 2026.8** or newer.

---

## Please check after updating

- Your entities are the same as before (count on the integration page).
- After a restart of Home Assistant, the diagnostics show `start_path`
  (`fast` from the second start on) and how long the start took.
- Changing an activity or the inputs in the options works as before.
- After the receiver restarts, the integration carries on by itself.

Report anything odd in a GitHub issue, with the diagnostics.

## Changed

- **Which entities there are** comes from one plan per platform. Once the
  receiver has answered everything after a start, the integration compares
  it with what the entities were built from and sets itself up once more if
  they differ. This now happens after every start, not only after the fast
  one: quick selects or speakers that come after the receiver's first
  answers get their entity at once instead of after the next restart.
- **Entities your options leave out** (a hidden zone, a zone without
  activities) are removed. An entity whose function the receiver did not
  report at one start keeps its entry, with your name and room.
- **The integration's own bookkeeping** (which speakers the channel
  defaults were applied for, which entities a group turned on, whether Zone
  2's inputs were chosen) lives in a store of its own instead of the
  options. Changing it no longer runs the options listener.
- The capability check and the command test chosen when the receiver was
  added start once the start is settled; a reload at the first start no
  longer cuts them off.
- Offline starts use the encodings of the receiver's generation and brand,
  as online ones do.
- The diagnostics show how the start went (`start_path`: `fast`,
  `preloaded`, `full`, `offline`).

## Fixed

- **The diagnostics contained the receiver's MAC address** in the unique
  ids of entities an entity group had turned on. They now give a count.
  Diagnostics you shared before may contain it.
- Taking another integration's entities over when the receiver was added:
  a reload while it ran could replace the record that *Move back* uses with
  an empty one.
- The protocol profile is checked when it is loaded: a misspelt key no
  longer reads as a missing function.
- A repair without its own flow is an error instead of opening the
  receiver test.

## Going back to 1.6

The entry is migrated to version 1.4; 1.6 still loads it. The markers stay
in the options as they were, and the two that are set once (channel
defaults applied, Zone 2 inputs chosen) are kept there too, so 1.6 chooses
nothing again. Entity groups switched in 1.6 after going back are not seen
by 1.7 when you update again: switch those groups once more.

## Tested

- 1121 tests pass on Home Assistant 2026.8 and 2026.10; ruff, strict typing,
  the coverage per module and the repository checks pass; the entity
  snapshot of the recorded AVC-X3700H is unchanged.
- An independent review of the changes; its findings are fixed, each with a
  test that failed without the fix.
- Not yet run on a receiver: this beta is for that (AVR-X2600H, AVR-X2000).
