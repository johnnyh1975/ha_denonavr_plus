# Denon AVR Plus 0.1.0

**The first release of Denon AVR Plus, an independent continuation of
LaserGuruGuy's Denon AVR 1.1.2 for Denon and Marantz receivers: older
receivers are set up on port 80, the media players keep working over the
web interface when telnet is taken, your commands no longer wait behind
the receiver's status queries, the now-playing info follows the receiver
and not other HEOS speakers in the house, only the everyday controls start
enabled, and the texts come in eight languages with entity ids that stay
English in every one.**

Needs **Home Assistant 2026.8** or newer. Coming from another Denon
integration: [upgrade notes →](../docs/UPGRADING.md#coming-from-another-denon-integration)

---

## A separate integration

Denon AVR Plus has its own domain, `denonavr_plus`, so it installs next to
the official Denon AVR integration and next to Denon AVR (`denon_avr`).
Both credit lines stay in the MIT licence. Do not connect two integrations
to the same receiver at once: many receivers accept only one telnet
session.

## Older receivers on port 80

Receivers from 2016 on serve their web interface on port 8080, older ones
on port 80. Port 8080 was fixed in the code, so an AVR-X2000 or AVR-X1100W
could not be set up.

The port is now chosen by what the receiver reports about itself
(`CommApiVers` in `Deviceinfo.xml`): 8080 first, and port 80 only when
the receiver there reports an interface older than 0301. A newer receiver
whose port 8080 is not up yet, because it is still waking, is not stored
on port 80. That is what keeps going wrong in the official integration
(home-assistant/core#163759). Redirects to HTTPS on port 80 are not
followed. The port is stored in the entry.

## When telnet is not available

The receiver allows one telnet session. When another program holds it,
or port 23 is blocked between networks, the integration used to go
unavailable without saying why.

- **The media players keep working.** While telnet is down but the
  receiver answers over HTTP, power, volume, mute and source of every
  zone are read every 10 seconds instead of every 60, and commands go
  over HTTP (`formiPhoneAppDirect.xml`), as the denonavr library does.
  The other settings need telnet and are unavailable until it is back.
- **A repair says why.** If telnet stays down for 5 minutes while HTTP
  answers, a repair names the likely causes: another integration holds
  the session, or a firewall rule blocks port 23. It disappears once
  telnet is back. If the receiver does not answer at all, which is often
  intended (off without network standby), there is only a warning in the
  log.

## Commands first, paced by the receiver

After every reconnect the integration sends about 65 status queries. A
volume change pressed at that moment waited behind them.

- Commands now go before queries still waiting in the queue.
- Instead of a fixed 100 ms pause between commands, the integration waits
  for the receiver's reply, at least 80 ms. A command that sets the
  current value gets no reply, so that wait ends after four times the
  measured response time, between 0.2 and 1 second. After `PWON` it waits
  1 second, as both Denon protocol documents ask.
- Whatever is still queued when the link drops is discarded, so nothing
  stale is sent after a reconnect.
- The measured response time is in the diagnostics
  (`telnet_response_ms`).

Fixed on the way: unloading the integration while a dropped link was
still closing raised an error.

## Now playing from the receiver, not from another speaker

HEOS lists every HEOS device in the house. The integration took the
first one, so with a HEOS speaker in the kitchen the receiver could show
the kitchen's title, and the speaker's play and pause changed the
receiver's state.

The receiver's own player is now found by its IP address, and events of
other players are ignored. When HEOS reports *stop*, the title is cleared.

## Fewer entities to start with

A receiver registers well over a hundred entities. Only what you change
while listening now starts enabled:

- the media players, the sound mode selects and quick select
- tone, Dynamic EQ, Dynamic Volume, Dynamic Compression, MultEQ, Cinema
  EQ, dialogue level and Dialog Control
- subwoofer on/off and level, All Zone Stereo, sleep timer, display
  dimmer
- the trims of the speakers the receiver has configured
- the decoder, volume and connectivity sensors

Everything else starts disabled: speaker setup, video and HDMI setup,
picture adjustment, the graphic EQ, volume limits, sound mode parameters,
and the power and mute switches, which repeat the media player. So do the
sample rate, input signal, audio format and mode info sensors, which
change with every track. Enable any of them on the device page. On the
recorded AVC-X3700H, 47 of 120 entities start enabled.

The volume sensor keeps no long-term statistics any more. Quick select
moved from the configuration section to the controls.

## Eight languages, English entity ids

The texts come in English, German, French, Italian, Spanish, Portuguese,
Dutch and Polish. Feature names that the receivers show in English stay
English (MultEQ, Dynamic EQ, Cinema EQ, All Zone Stereo, Quick Select,
DTS Neural:X).

Home Assistant builds entity ids from the name in the user's language for
many languages, German and Dutch among them. Here they are always built
from the English name, so `number.avr_x3600h_speakers_center_trim` is the
same in every installation while the name on screen is translated
("Center Pegel"). Names made from what the receiver reports ("Center
Trim", "Front Speaker Size", "Zone 2") translate their fixed part. The
sub-devices keep their English names (Audio, Video, Picture, Speakers,
Graphic EQ), because those are part of every entity id.

## Settings the receiver refuses

The graphic EQ, video and speaker setup are written over the receiver's
setup interface. When the receiver refused a write, the old value simply
came back. Now Home Assistant shows an error that says what to check
(the setup menu open on the TV, the setup lock), and the graphic EQ keeps
your staged band changes so you can try again.

## Diagnostics

The diagnostics never contained the address; they now leave out the
serial number as well as the MAC. New in them: the web interface port and
the telnet response time.

## A probe for any receiver

`tools/probe_receiver.py` asks a Denon or Marantz receiver about 150
documented questions, reads its web pages, HEOS players and setup
interface, and writes what it can do as a table and as raw data. It only
reads: anything but a query or one of three documented read requests is
refused before it is sent.
Addresses, MAC, serial number and device names are replaced in the
output. It needs nothing but Python 3.10. Results from other models help
most: see *Contributing* in the README.

## Tested

- 171 tests pass on Home Assistant 2026.8 and 2026.10, among them 28
  recorded receiver descriptions from the denonavr library; ruff, the
  typing baseline, the coverage floors, the translation check and the
  locale-slug guard pass.
- The tests of the fixes fail without them, among them the port choice,
  the HEOS player, the dropped queue and the English entity ids in all
  eight languages.
- **None of these changes has been on a receiver yet.** The pacing values
  come from Denon's protocol documents and owners' reports, not from a
  measurement. LaserGuruGuy tested the code this release starts from on
  an AVR-X3600H.
- The AVR-X2000 generation can be set up now, but it reports few of its
  functions, so most of its settings stay hidden, and its older value
  formats are not handled yet.
