# Denon AVR Plus 1.0.0

**Version 1.0: the receiver says why it keeps a setting, the sound settings
stay usable without telnet, firmware updates appear under Settings →
Updates, and a volume ramp for wake-ups and fade-outs.**

Needs **Home Assistant 2026.8** or newer. After updating, reload the Home
Assistant app or page once, so it shows the new texts. Read
[Upgrading](https://github.com/johnnyh1975/ha_denonavr_plus/blob/main/docs/UPGRADING.md)
first: a setting the receiver keeps now stops an automation with an error.

---

## New

- **The reason when the receiver keeps a setting.** Some settings work only
  in a context, and in standby the receiver takes none. Where that is known,
  the integration waits for the receiver to confirm the new value and
  otherwise says why it kept the old one: Dynamic Compression, Loudness
  Management and LFE only with a Dolby or DTS signal, Dialog Control only
  with DTS:X, the effect level only in a DSP mode, the subwoofer off only in
  Direct, Pure Direct or Stereo, Front speakers A/B only with the amp
  assignment Front B, the HDMI resolution only with the i/p scaler on HDMI,
  the graphic EQ only with MultEQ off, bass and treble only with Tone Control
  on and Dynamic EQ off, picture settings only in the Custom picture mode.
- **Without telnet, the sound settings stay.** When another app holds the
  control connection or port 23 is blocked, the integration now also reads
  the sound mode and tone control (receivers from 2013) and MultEQ, Dynamic
  EQ and Dynamic Volume (from 2014) over the web interface, as the official
  integration does. These settings stay available and can be changed;
  before, only power, volume, mute and source were left.
- **Firmware under Settings → Updates.** On receivers with HEOS an update
  entity shows the installed firmware and, when HEOS reports an update,
  "Newer version". HEOS names no version, so none is made up; the update is
  installed from the receiver's menu or the HEOS app. The diagnostic binary
  sensor stays for automations.
- **Volume ramp** (`denonavr_plus.volume_ramp`): the volume to a level over a
  number of seconds, in the receiver's own steps, for a wake-up or a
  fade-out. A new ramp, a volume command or switching the zone off stops it.
- **Zone 2's inputs, asked once.** After setup a repair asks which inputs
  Zone 2 can play. Smaller receivers play no HDMI input there; when the
  receiver reports no HDMI for Zone 2, the HDMI inputs start deselected.
  Receivers that report it get a Zone 2 *HDMI audio* select (through or PCM).
- **The tuner from the tuner entities.** Choosing a tuner preset or an FM
  frequency switches the main zone to the tuner first. While no zone plays
  the tuner, these entities are *unknown* instead of *unavailable*.
- **Options as the receiver lists them.** Video Mode offers Bypass and the
  HDMI resolution 8K where the receiver lists them; Input Mode no longer
  offers eARC on receivers without it.

## Faster

- **A quicker start.** The answers to the queries after connecting no longer
  start the same queries again (the sound mode list was asked for five times
  in the first seconds), and the parts of the discovery are read together.
  The diagnostics show how long each part took.

## Documentation

## Tested

- 754 tests pass on Home Assistant 2026.8 and 2026.10; ruff, strict typing,
  the coverage per module and the repository checks pass.
- The reasons for kept settings come from the receiver test of an AVR-X2000
  and an AVR-X2600H. The web interface reads follow the official library;
  its recordings cover the sound mode and tone control, not yet the
  Audyssey answer. The Zone 2 HDMI query is answered by an AVR-X2000, and
  the inputs that carry HDMI are those of the X series as delivered. The
  volume ramp and the firmware entity are not yet tried on a receiver.
