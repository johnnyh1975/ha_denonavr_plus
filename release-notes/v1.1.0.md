# Denon AVR Plus 1.1.0

**Readable sound mode names, help when the receiver does not take its
control connection, an option to switch it on for a setting, and a faster
start.**

Needs **Home Assistant 2026.8** or newer. After updating, reload the Home
Assistant app or page once, so it shows the new texts. Read
[Upgrading](https://github.com/johnnyh1975/ha_denonavr_plus/blob/main/docs/UPGRADING.md)
first: the sound mode names change.

---

## New

- **Readable sound mode names.** The media player and the sound mode select
  show *Dolby Surround* where the receiver says *Dolby Audio - DD + DSur*,
  the Dolby format spelled out, and *Multichannel stereo* and *Multichannel
  input* in your language. Other names stay as the receiver gives them; two
  modes that would get the same short name keep the receiver's names, and a
  name you set wins. A mode has the same name in the player and the select.
  The receiver's names still choose a mode in both, in any case. Switch
  **Readable names** off under Configure → Sound modes to keep the receiver's
  names.
- **Help when the receiver does not take its control connection.** When the
  receiver answers on the network but not on its control connection (telnet,
  port 23), setup names the usual causes: another integration or program
  holding the receiver's one connection, the AVR Remote app with its tuner
  screen open, a firewall rule. Check again, or go on: the integration then
  works over the web interface and connects once the port is free. When the
  receiver does not answer at all, the message names Network Standby.
- **Turn the receiver on for a setting** (Configure → Zones and power,
  default off): a select, switch or number of the main zone changed while
  the receiver is in standby turns the main zone on first, instead of
  reporting that the receiver is in standby. A value it already has turns
  nothing on. Receivers with one zone now get this step too.
- **Control by apps.** The integration asks whether the receiver allows
  control by Denon's apps (`NSARA`, `NSHEA`). The answers are in the
  diagnostics and the receiver test; when control by the remote app is
  switched off, a repair says so.
- **Receiver report with one click.** The receiver test's result links to a
  new report in Discussions, with model, firmware and version filled in
  where GitHub takes them over.
- **Number ranges from the receiver.** Audio Delay, Containment Amount and
  Dialog Control take the range the receiver describes, also on older
  receivers such as the AVR-X2100W.

## Faster

- **A quicker later start.** From the second start on, the speaker setup,
  the quick select names and the inputs come from the last start, and setup
  waits only for the receiver's first answer; the current values follow
  within seconds. The diagnostics show the times (`setup_timings_ms`).

## Fixed

Found in two independent reviews before the release:

- The control connection check at setup no longer ends in an unknown error
  when the receiver accepts the connection and then drops it.
- The repair for control by apps goes away with the session.
- The faster start keeps what the current start learned and saves the
  receiver's current values, not the last start's.
- Which sound mode a name chooses no longer depends on its case or on the
  order of the list.

## Tested

- 805 tests pass on Home Assistant 2026.8 and 2026.10; ruff, strict typing,
  the coverage per module and the repository checks pass.
- Not yet tried on a receiver: the answers to `NSARA` and `NSHEA` (no
  receiver has answered them yet), the prefilled report form (GitHub
  documents prefilling for issues only; otherwise the empty form opens),
  the time the faster start saves, and the three seconds the receiver gets
  after switching on for a setting (taken from the AVR-X2000).
