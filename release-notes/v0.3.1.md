# Denon AVR Plus 0.3.1

**Fixes from an independent review of 0.3.0: no reload loop when the
receiver answers over telnet before its web interface, the capability
check no longer keeps the receiver's name, serial number or MAC in the
diagnostics, "turn off" no longer fails for a receiver that does not
answer, and model-dependent controls no longer disappear after one late
reply.**

Needs **Home Assistant 2026.8** or newer. Nothing to change when coming
from 0.3.0. Coming from 0.2.0: [upgrade notes →](../docs/UPGRADING.md#from-020)

Update before you run the capability check, so the diagnostics file you
attach to GitHub is cleaned properly.

---

## Fixed

- **Reload loop.** After a start without the receiver, the integration
  reloaded as soon as telnet answered. If the receiver's web interface did
  not answer yet (still booting, or port 8080 blocked), the reload started
  without it again, and so on: hundreds of telnet sessions in seconds. It
  now reloads only once the receiver's device description answers, and
  tries at most once a minute.
- **Capability check privacy.** The diagnostics kept the name you gave the
  receiver, its MAC written without separators, its serial number and IPv6
  addresses. They are replaced now in every answer, as the probe script
  does.
- **Turning off a receiver that does not answer.** With a "Turn on
  requested" automation the player shows off while the receiver does not
  answer; turning it off then raised an error and stopped automations
  such as "everything off". It now does nothing, and only on and off are
  offered in that state.
- **Model-dependent controls kept.** IMAX, Auro-3D, the triggers and the
  other controls that appear only when the receiver answers their query
  are no longer lost when one answer comes late at a start: a control the
  receiver has answered once stays.
- **Capability check.** Answers are timed from when the question was sent,
  not from when it was queued, so fewer are counted as missing. Checks run
  one at a time. Any error ends the dialog with a message instead of an
  error. The "Help support" repair survives a reload.
- **Discovery.** A receiver announcing itself several times at once now
  starts one setup and reads its device description once.
- **Unloading during a HEOS reconnect.** Removing or reloading the
  integration while the HEOS connection was being re-opened could end with
  an error; the HEOS client now closes its connection the way the telnet
  client does.
- **Faster start.** Asking for the model-dependent controls no longer waits
  two seconds for answers that a model without them never sends; it ends
  as soon as the receiver stops answering.
- **Smaller fixes:**
  - The `send_command` field description showed `{max_length}` instead of
    134.
  - Without HEOS, the player no longer offers play and pause.
  - The device page links to port 11080 where 10443 is closed.
  - A failed setup says why, in your language.
  - The stored discovery no longer loses the source list.

## Unconfirmed on a receiver

The 0.3.0 notes left out three commands: the buttons to save a quick
select preset (`MSQUICK<n> MEMORY`), reset the channel levels (`CVZRL`)
and restart the network module (`NSRBT`). Like the remote keys, the
model-dependent controls, port 11080 and the `send_command` length limit,
they are taken from documents or the denonavr library and have not been
tried on a receiver yet.

## Tested

- 359 tests pass on Home Assistant 2026.8 and 2026.10; ruff, the typing
  baseline (down from 88 to 86 findings), the coverage floors, the
  translation, locale-slug and icon checks pass.
- Each fix has a test that fails without it. Every model-dependent control
  now has a test of its reply format.
- None of these changes has been on a receiver yet.
