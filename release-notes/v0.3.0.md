# Denon AVR Plus 0.3.0

**Marantz and older receivers are discovered and can be set up without
typing an address; the address follows the receiver when it changes; a
receiver off without network standby can be switched on through an
automation, also after a restart of Home Assistant; a capability check
helps support models that have not been checked yet; a remote for the
on-screen menu, a `send_command` action, model-dependent controls such as
IMAX, Auro-3D, Dirac and the 12 V triggers, select options in every
language, and a clear error when a setting does not reach the receiver.**

Needs **Home Assistant 2026.8** or newer. Coming from 0.2.0, select options
are now keys: [upgrade notes →](../docs/UPGRADING.md#from-020)

---

## Finding and keeping the receiver

- **Marantz and every Denon spelling.** Discovery matched only one device
  type under the name `Denon`. It now matches the same twelve
  announcements as the official integration (Denon, DENON, DENON
  PROFESSIONAL, Marantz), so Marantz units and receivers from before 2016
  are found too. HEOS speakers are skipped, and a receiver that announces
  itself several times starts one discovery.
- **Setup without an address.** Leave the address field empty to choose
  from the receivers Home Assistant has found; with only one, it is added
  directly.
- **A new address is followed.** When the router gives the receiver a new
  address, the integration notices it over DHCP and takes it over.

## Switching on a receiver that does not answer

With network standby off, a receiver that is off is gone from the network.

- **Device trigger "Turn on requested".** Build an automation with it that
  switches the receiver on by infrared or HDMI-CEC. While such an
  automation exists, the media players stay usable and show off; turning
  one on runs the automation.
- **Start without the receiver.** The integration keeps what it read the
  last time it reached the receiver. After a restart of Home Assistant
  while the receiver is off, the media players are set up from that, so
  the trigger works then too. As soon as the receiver answers, everything
  else comes back by itself.

## Capability check

Models that have not been checked with this integration (so far all but
the AVR-X3600H) can now be checked from Home Assistant:

- when such a receiver is added, setup offers to run the check once it is
  connected;
- a repair asks for it later, and **Configure → Check capabilities** runs
  it any time.

It asks the receiver about 150 read-only questions over the integration's
own connection, takes up to a minute and a half and changes nothing. The
answers go into the diagnostics file, with addresses replaced. A repair
then links to a prefilled issue on GitHub, where you attach the file.
Nothing is sent anywhere by itself.

## New controls

- **Remote.** `remote.<receiver>_remote` drives the on-screen menu: cursor
  keys, enter, back, option, info, the channel level menu and the setup
  menu.
- **Send command.** `denonavr_plus.send_command` sends a raw telnet
  command, such as `PSDYNEQ ON`; asked for a response, it returns the
  receiver's replies. It replaces `denonavr.get_command`.
- **Model-dependent controls,** created only when the receiver answers
  their query at setup: Auto Standby, 12 V Triggers 1 and 2, Speaker
  Preset, Bluetooth Transmitter, Dialogue Enhancer, Effect Speakers, IMAX,
  Auro-Matic 3D and Auro-3D mode, Dirac Live filter slot, Tactile
  Transducer, and on Marantz M-DAX, DAC Filter and Illumination.
- **Buttons** to save a quick select preset, reset all channel levels and
  restart the network module. They start disabled.

## Options

**Configure → Connection**, which opens even when the receiver is off:

- **Check interval** of the HTTP check while telnet is connected, 30 to
  600 seconds.
- **Now playing over HEOS** can be switched off.
- **Read setup settings every** … minutes. The graphic EQ, video setup and
  amp assign used to be read with every check, up to seven requests a
  minute. They are now read when the connection comes up, after every
  change from Home Assistant, and every 15 minutes (0: never).

## Select options in your language

Selects with a fixed set of options (dimmer, MultEQ, Dynamic Volume,
speaker size, video setup and the others, 32 in all) show their options in
your language. Their state is now a key such as `dark` or `medium_small`.
**Automations that set or compare such an option need the key**; the
upgrade notes list how the keys are formed.

## Errors you can see

- A setting that reaches the receiver neither over telnet nor over the web
  interface used to be dropped silently. Now Home Assistant says that the
  receiver could not be reached.
- The device page showed the protocol family (avr-x-2016) as the hardware
  version; it is gone.
- Reconfigure accepted an empty address and then failed; it asks for the
  address again.

## Behind the scenes

- Every entity takes its icon from `icons.json`; power and mute show their
  state.
- The HEOS connection sends a heartbeat after 10 seconds of silence and
  reconnects when it gets no answer, so now playing no longer goes stale
  after a silently dropped link.
- When the setup interface on port 10443 does not accept a connection,
  port 11080 is tried (newer firmware is reported to use it).
- Sleep timer and audio delay are durations; every platform declares how
  many updates may run at once.
