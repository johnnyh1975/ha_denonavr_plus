# Denon AVR Plus 0.2.0

**Volume in dB per zone, with a maximum Home Assistant never exceeds and a
turn-on volume; the volume scale of the official integration, so
automations sound the same after moving over; options to choose and rename
sources and sound modes and to switch off unused zones; a source sensor
per zone; versioned config entries that migrate themselves; and a probe
that now reads everything the integration uses.**

Needs **Home Assistant 2026.8** or newer. Coming from 0.1.0, the volume
sensor is replaced: [upgrade notes →](../docs/UPGRADING.md#from-010)

---

## Volume in dB

The volume was a read-only sensor. It is now a number per zone that you
can set, in dB as the receiver shows it, from −80 dB up to the receiver's
maximum (`number.<receiver>_volume`, `number.<receiver>_zone_2_volume`).
Like the media player, it keeps working over HTTP while telnet is down.

The old sensor is removed at the first start. An automation, script or
dashboard that used it has to point to the number; the value is the same.

## Options

**Configure** on the integration entry now opens a menu: volume, zones,
sources and sound modes. Nothing in it changes the receiver; it changes
what Home Assistant shows and does.

### Volume

- **Volume scale of the official integration.** Off, the media player's
  0 to 100 % spans the receiver's whole range up to its maximum, as
  before. On, 100 % is +20 dB and 0 % is −80 dB, as the official Denon
  AVR integration computes it, so `volume_set` levels in automations sound
  the same after moving over.
- **Maximum volume per zone.** Home Assistant never sets the zone louder,
  whether from the media player, the volume number or volume up. The
  receiver's own buttons and remote are not limited; for that, use its
  Volume Limit setting.
- **Turn-on volume per zone.** Set when Home Assistant switches the zone
  on, once the zone reports that it is on.

These options open even when the receiver is off.

### Sources and sound modes

- **Sources**, per zone: which sources the media player offers, then a
  name for each. The names and hidden inputs set on the receiver are
  already taken over; this narrows down and renames on top. Choosing all
  keeps sources the receiver gains later. Renamed sources can still be
  selected by their receiver name, so older automations keep working.
- **Sound modes** of the main zone: which ones the media player offers,
  and their names. The sound mode selects keep the receiver's full list.
- The current source and sound mode are always shown, also when they are
  not among the chosen ones.

Both need the receiver connected, since they read its lists.

### Zones

Zone 2 and zone 3 can be switched off. Their media player, volume and
source sensor are then removed; switching the zone on again brings them
back.

## A source sensor per zone

`sensor.<receiver>_source` shows the current source under the name Home
Assistant shows, for history and for automations that only need to read
it. It starts disabled, as it repeats the media player.

## Entries that migrate themselves

Config entries now carry a version. When a release changes what is stored
(entry data, options, unique ids, device identifiers), a migration step
brings older entries along at the first start. The first step is in this
release: it removes the old volume sensor. An entry from a newer release,
after a downgrade, still loads as long as only the minor version is
newer.

Every entity of a recorded AVC-X3700H is pinned in the tests with its id,
start state and category, so an entity id cannot change by accident. On
that recording 48 of 123 entities start enabled.

## The probe reads everything the integration uses

`tools/probe_receiver.py` is more complete, and still only reads:

- the zone 2 and zone 3 status pages, the receiver's AppCommand interface
  (Get requests only) and the setup pages the integration reads;
- a scan of the setup interface, so it shows which settings a model
  offers there;
- the reply time of every query, a test of how closely queries may follow
  each other, and whether the receiver accepts a second telnet session;
- SSDP, more HEOS details, which zones were on, and a warning when the
  receiver is in standby;
- anonymisation also of the Wi-Fi MAC and name, accounts, e-mail and IPv6
  addresses, and the names of the receiver and other HEOS speakers.

Results from other models help most: see *Contributing* in the README.

## Documentation

Every query the integration sends is now described in the protocol pages
under `docs/protocol/`; a test fails when one is added without them. Six
sound-mode tokens were missing and are added.

The 0.1.0 notes said 46 of 116 entities start enabled on the recorded
receiver; it was 47 of 120.

## Tested

- 214 tests pass on Home Assistant 2026.8 and 2026.10; ruff, the typing
  baseline (down from 92 to 90 findings), the coverage floors, the
  translation check and the locale-slug guard pass.
- The tests cover the volume scales and limits, the turn-on volume, the
  source and sound mode choice with renaming, the zone removal, the
  migration chain and the entity snapshot.
- **None of these changes has been on a receiver yet.** The volume number,
  the turn-on volume and the zone options are the first things to check
  on a real receiver.
